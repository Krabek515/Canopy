# Контекст для продолжения работы (handoff)

Этот файл — снимок состояния на момент коммита-точки-восстановления.
Написан для агента, который продолжит работу (Claude / Devin). Источник правды
по замыслу — `docs/`, читать в порядке `00-index.md`.

## Что за проект

Canopy — мод на Forge 1.20.1, мир целиком из джунглей, выживание вместо шахт.
Базу сделал Grok: системы тела/ран/дневника рабочие, но текстуры, генерация
мира и модели зверей были кривыми. Второй этап — переделка визуала и новый
контент — завершён и проверен сборкой + прогоном сервера.

## Что уже сделано и работает

- `tools/art/` — генератор пиксельных текстур на Java с общей палитрой
  (sprite16/sprite, canvas + noise, контрольные листы preview*.png).
  Все текстуры предметов, блоков, GUI, HUD и зверей перерисованы.
- Лес: `world/JungleTrees.java` — 8 форм деревьев; новые растения (бромелия
  с дождевой водой для фляги, лиана-водонос, геликония, имбирная лилия,
  трутовик); биомы по 4 параметрам шума; стенки каньона слоями терракоты/ила.
- GeckoLib 4.8.4: 9 зверей — ягуар, обезьяна, змея, агути + капибара, тапир,
  кайман, горилла, тукан. `client/BeastRenderer` — один на всех по имени.
- `BeastSpawn.waterNear()` — проверка воды только внутри чанка (фикс краша
  генерации «region out of bound»).
- Мокрый сезон — `world/WetSeason.java` + конфиг `drySeasonDays`/
  `wetSeasonDays`: в мокрые дни ливень и паводок вдвое чаще, дождь почти
  не стихает. Сообщение сезона — раз на смену.
- Лагерь: `StiltPlatformBlock` (настил, стоит и над водой до 4 блоков до дна,
  waterlogged) + `HammockBlock` (наследник BedBlock — ванильный сон и респаун;
  концы должны упираться в стволы/стойки, иначе сообщение). Рендер —
  `client/HammockRenderer` со своим BlockEntity и провисшим полотном.
- Глиняная печь — `ClayOvenBlock`: ПКМ кладёт порции из тега
  `canopy:stew_ingredients` (raw_meat, taro_root, log_fungus), при ≥2 и огне
  под печью тик 45с → `ready`, ПКМ забирает `canopy:stew`.
- Каучук: `RubberKnotBlock` встаёт вместо бревна внизу ствола во влажных
  биомах через `ForestDress` (VERSION=4); зубило снимает `rubber_sap`
  (`tapped` → восстановление случайным тиком). Рецепт `canopy:waxing` —
  свой `RecipeSerializer` (`item/WaxRecipe.ts`, регистрация в
  `item/CanopyRecipes.java`), ставит на одежду NBT `Waxed` →
  `WornClothing.wetGain` −0.18 за вещь.
- Костяное мачете: `bone_shard` падает с тапира/капибары/каймана/гориллы,
  рецепт 2 осколка + бамбук, тир между каменным и металлическим.
- HUD (`client/VitalsHud.java`): иконки 9×9 (`textures/hud/icons.png`) +
  полоски, текст только для предупреждений.

## Что осталось — шлифовка, не столпы

1. **Проверить глазами в клиенте**: geo-модели/анимации зверей, полотно
   гамака (BER), модели печи/настила, HUD-иконки. Серверный прогон чист,
   но визуал в движении не смотрелся.
2. Спавн капибары/тапира/каймана — правила в `BeastSpawn` (shore/shallows/
   canopy), в биомах веса есть; в короткой переписи не встретились —
   проверить в длинной сессии.
3. Собственные звуки — всё ещё события ванили (сознательно).
4. Обрывки истории экспедиции — из замысла, не делались.
5. Баланс чисел (жажда/сырость/урон зверей) — полевой фидбек.

## Как проверять

- Компиляция: `gradlew.bat compileJava` (Java 21 на машине, toolchain 17).
- Сервер: `gradlew.bat runServer` → `/canopy census` — перепись блоков
  вокруг спавна (rubber_knot=83 подтверждён).
- Арт: `javac -d tools/art/out tools/art/*.java && java -cp tools/art/out Art`
  → `tools/art/preview.png`, `preview_entities.png`.
